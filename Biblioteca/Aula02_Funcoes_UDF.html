1. O que é uma função

Uma função definida pelo usuário (UDF, do inglês User-Defined Function) é uma regra que você escreve e guarda dentro do banco. Ela funciona como uma máquina: recebe valores (os parâmetros), faz uma conta e devolve um único valor.

Você já usa funções prontas do MySQL, como ROUND, UPPER e COUNT. Com a UDF, você cria as suas, com as regras do seu negócio.

SELECT fn_preco_com_desconto(250, 15); → 212.50

CaracterísticaO que quer dizer
Recebe parâmetrosZero ou mais valores de entrada, cada um com um tipo (INT, DECIMAL(10,2), VARCHAR(100)…).
Devolve um valorSempre um só, do tipo declarado em RETURNS.
Usada dentro de comandosAparece em SELECT, WHERE, ORDER BY, UPDATE ... SET, como qualquer função do MySQL.
Fica guardada no bancoPertence a um banco (ex.: loja_teste). Vai junto no backup e sobrevive ao contêiner, porque mora no volume.

2. Anatomia do CREATE FUNCTION

Clique (ou use Tab e Enter) em cada parte do código para ver o que ela faz.

DROP FUNCTION IF EXISTS fn_situacao_estoque;

CREATE FUNCTION fn_situacao_estoque(p_qtd INT)
RETURNS VARCHAR(10)
DETERMINISTIC
RETURN CASE
         WHEN p_qtd < 10  THEN 'Repor'
         WHEN p_qtd < 20  THEN 'Atenção'
         WHEN p_qtd >= 60 THEN 'Excesso'
         ELSE 'OK'
       END;

SELECT nome, estoque, fn_situacao_estoque(estoque)
  FROM produtos;

4. Uma chamada por linha

Quando a função aparece no SELECT, o MySQL a executa uma vez para cada linha do resultado. Aperte o botão e acompanhe.

SELECT nome, preco, fn_preco_com_desconto(preco, 10) AS promo
  FROM produtos WHERE categoria = 'Livros';
Execuções da função: 0
nomeprecopromo

Com 5 linhas, tudo bem. Com 5 milhões, uma função lenta multiplica o tempo da consulta. Você vai medir isso na Aula 15 (performance).

6. A ordem das condições importa

Num IF ... ELSEIF ou num CASE, o MySQL testa as condições de cima para baixo e para na primeira verdadeira. Se a ordem estiver errada, a função cria a regra errada sem dar erro nenhum.

Exemplo: desconto por valor da compra. R$ 1.000 ou mais ganham 15%; R$ 500 ou mais, 10%; R$ 200 ou mais, 5%.

Valor testadoEsperadoA função devolveuResultado

Regra prática: com faixas do tipo "a partir de", comece pela condição mais restritiva (o maior valor). E sempre escreva testes para os limites: 199,99, 200, 500, 1000.

7.2 Valor da parcela (matemática financeira)

Parcelamento com juros pela tabela Price: parcela = valor × i ÷ (1 − (1 + i)−n). A função trata dois casos especiais: número de parcelas inválido e juros zero.

DELIMITER $$
CREATE FUNCTION fn_parcela(p_valor DECIMAL(10,2), p_n INT, p_juros_mes DECIMAL(5,2))
RETURNS DECIMAL(10,2)
DETERMINISTIC
BEGIN
    DECLARE v_i DOUBLE;

    IF p_n <= 0 THEN
        RETURN NULL;                       -- número de parcelas inválido
    END IF;

    SET v_i = p_juros_mes / 100;

    IF v_i = 0 THEN
        RETURN ROUND(p_valor / p_n, 2);    -- sem juros
    END IF;

    RETURN ROUND(p_valor * v_i / (1 - POW(1 + v_i, -p_n)), 2);
END $$
DELIMITER ;
–valor de cada parcela
–total pago
–juros pagos

Total pago conforme o número de parcelas. A barra laranja é a escolha atual.

7.3 Mascarar e-mail (texto e LGPD)

Uma tela de atendimento não precisa mostrar o e-mail completo do cliente. A função esconde o meio do endereço. Você vai usar ideias assim na Aula 09, sobre LGPD.

DELIMITER $$
CREATE FUNCTION fn_mascara_email(p_email VARCHAR(100))
RETURNS VARCHAR(100)
DETERMINISTIC
BEGIN
    DECLARE v_arroba INT DEFAULT LOCATE('@', p_email);

    IF v_arroba <= 3 THEN
        RETURN p_email;                    -- usuário curto demais para mascarar
    END IF;

    RETURN CONCAT(LEFT(p_email, 2),
                  REPEAT('*', v_arroba - 3),
                  SUBSTRING(p_email, v_arroba));
END $$
DELIMITER ;

7.4 Função que lê o banco (READS SQL DATA)

Uma função também pode consultar tabelas. Esta conta quantos pedidos válidos cada cliente fez. Repare no SELECT ... INTO, que guarda o resultado da consulta numa variável.

DELIMITER $$
CREATE FUNCTION fn_qtd_pedidos(p_cliente_id INT)
RETURNS INT
READS SQL DATA
BEGIN
    DECLARE v_qtd INT;

    SELECT COUNT(*) INTO v_qtd
      FROM pedidos
     WHERE cliente_id = p_cliente_id
       AND status <> 'Cancelado';

    RETURN v_qtd;
END $$
DELIMITER ;

SELECT nome, fn_qtd_pedidos(id) AS pedidos
  FROM clientes ORDER BY pedidos DESC, nome LIMIT 5;

8. DETERMINISTIC e companhia

O MySQL 8.4 grava um log binário com tudo o que muda no banco. Esse log é usado em backups e réplicas (você vai ver na Aula 12). Por isso, ele exige que cada função diga como se comporta. Sem isso, aparece o erro 1418.

CaracterísticaQuer dizerExemplo
DETERMINISTICMesmas entradas, sempre o mesmo resultado.fn_frete, fn_parcela
NOT DETERMINISTICO resultado pode mudar mesmo com as mesmas entradas. É o padrão, se você não escrever nada.Uma função que usa NOW() ou RAND()
READS SQL DATALê tabelas, mas não altera nada.fn_qtd_pedidos
NO SQLNão tem nenhum comando SQL dentro, só cálculo.Uma conversão de unidades

Não minta para o banco. Declarar DETERMINISTIC numa função que usa NOW() faz o erro sumir, mas pode gerar resultados diferentes num restore ou numa réplica.

11. Erros comuns

ERROR 1418: This function has none of DETERMINISTIC, NO SQL, or READS SQL DATA…

Faltou declarar a característica. Acrescente DETERMINISTIC (só calcula) ou READS SQL DATA (lê tabelas) logo depois do RETURNS.

ERROR 1304: FUNCTION fn_frete already exists

A função já existe. Rode DROP FUNCTION IF EXISTS fn_frete; antes do CREATE.

ERROR 1064: You have an error in your SQL syntax… near 'END'

Quase sempre é o delimitador. Confira se o DELIMITER $$ veio antes e se há $$ depois do END. Também vale procurar um ; esquecido no fim de alguma linha de dentro.

ERROR 1305: FUNCTION loja_teste.fn_frte does not exist

Nome digitado errado, ou você está em outro banco. Rode USE loja_teste; e confira com SHOW FUNCTION STATUS.

ERROR 1318: Incorrect number of arguments for FUNCTION…

A função foi chamada com parâmetros a mais ou a menos. fn_frete espera dois: a UF e o valor.

A função devolve NULL

A variável de retorno não recebeu valor em nenhum caminho. Falta um ELSE, ou a variável foi declarada sem DEFAULT. Também acontece quando um dos parâmetros chega como NULL.

ERROR 1172: Result consisted of more than one row

O SELECT ... INTO encontrou mais de uma linha. Uma variável guarda um valor só. Use uma função de agregação (COUNT, SUM) ou um filtro que traga uma linha só.

13. Para praticar

Desafios extras com a base da TechStore. Escreva, crie no seu banco e invente os seus testes antes de rodar.

  1. fn_prazo_entrega(p_uf): devolve o prazo em dias úteis. SP: 2; Sudeste: 4; Sul: 5; demais: 8. Depois, liste os pedidos com a data prevista de entrega usando DATE_ADD.
  2. fn_nome_curto(p_nome): devolve o primeiro nome e a inicial do sobrenome. "Ana Silva" vira "Ana S.". Dica: SUBSTRING_INDEX.
  3. fn_preco_final(p_preco, p_uf): combina duas funções, aplica a fn_faixa_desconto no preço e soma a fn_frete.
  4. fn_ticket_medio(p_cliente_id): lê o banco e devolve o valor médio dos pedidos não cancelados do cliente. Que característica ela precisa ter?
