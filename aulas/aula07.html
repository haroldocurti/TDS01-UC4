Na Aula 06, você pesquisou como as procedures são usadas e apresentou uma atividade. Hoje vamos transformar três necessidades da TechStore em rotinas de banco de dados. Cada uma acrescenta uma responsabilidade nova.

Para que serve esta aula

Você vai construir e testar procedures que consultam dados, validam uma mudança de status e registram um pedido com controle de estoque.

Esta UC não tem Projeto Integrador. O script que você construir passa a compor o Pacote de Rotinas da TechStore.

O que vamos observar no seu trabalho

  • Se os parâmetros representam os dados que a aplicação precisa enviar ou receber.
  • Se a consulta ou alteração segue o pedido da TechStore.
  • Se a procedure recusa entradas que quebrariam a regra do exercício.
  • Se você consegue explicar o que foi lido, gravado e confirmado.

Ponto de partida

Escolha uma atividade apresentada na aula anterior. Que dados a pessoa usuária informaria? A rotina devolveria uma lista, uma mensagem ou um número de pedido?

Antes de começar

Entre no MySQL usado na aula e selecione a base:

USE loja_teste;
SHOW FUNCTION STATUS WHERE Db = 'loja_teste';

Confira se aparecem fn_frete e fn_total_pedido. A terceira procedure usa as duas. Se alguma não aparecer, chame o docente antes de seguir.

O esquema da TechStore usa pedidos.data_pedido e itens_pedido.preco_unitario. Confira esses nomes antes de escrever os INSERTs.

O script de prática está em Aula07_procedures_techstore.sql. Complete os trechos TODO junto com este guia.

Execute cada seção depois de completar os trechos dela. A chamada feliz da terceira procedure altera o estoque e cria um pedido; rode essa chamada uma vez no banco de laboratório.

1. Procedure básica: listar produtos por categoria (30 min)

A primeira demanda é uma consulta. A aplicação envia uma categoria e a procedure devolve os produtos encontrados.

CALL sp_listar_produtos_categoria('Eletrônicos');

Construa a rotina em quatro passos:

  1. Defina a assinatura: sp_listar_produtos_categoria recebe p_categoria VARCHAR(50) como IN.
  2. Dentro de BEGIN ... END, faça um SELECT de id, nome, categoria, preco e estoque da tabela produtos.
  3. Filtre com WHERE categoria = p_categoria e ordene pelo nome.
  4. Crie a procedure com DELIMITER $$ e chame com CALL.

Teste com Eletrônicos, Alimentos e uma categoria que não exista. O terceiro teste deve retornar zero linhas sem gerar erro.

Pense: essa procedure muda algum dado? O que ela devolve para a aplicação?

2. Procedure intermediária: mudar status do pedido (40 min)

A equipe precisa impedir mudanças incoerentes no status. Para este exercício, use esta regra didática:

Status atual Próximos status permitidos
Pendente Processando ou Cancelado
Processando Entregue ou Cancelado
Entregue nenhum
Cancelado nenhum

Esta regra foi criada para praticar condições e validações. Uma aplicação real precisa confirmar as transições com a área de negócio.

Construa sp_atualizar_status_pedido(IN p_pedido_id INT, IN p_novo_status VARCHAR(20)):

  1. Declare uma variável para o status atual, uma para a mensagem e uma variável de controle iniciada em zero.
  2. Busque o status em pedidos pelo id recebido.
  3. Se o pedido não existir ou o novo status for NULL, use SIGNAL SQLSTATE '45000' com uma mensagem clara.
  4. Use IF e ELSEIF para marcar as transições permitidas.
  5. Se a transição não for permitida, monte a mensagem e use SIGNAL.
  6. Só então atualize pedidos.status e mostre o resultado.

Para testar sem deixar a base alterada, confira que há um pedido Processando e rode:

SET @pedido_teste = (
    SELECT id FROM pedidos
    WHERE status = 'Processando'
    ORDER BY id LIMIT 1
);
SELECT @pedido_teste;
START TRANSACTION;
CALL sp_atualizar_status_pedido(@pedido_teste, 'Entregue');
SELECT id, status FROM pedidos WHERE id = @pedido_teste;
ROLLBACK;

Se a variável aparecer como NULL, escolha um id retornado por SELECT id, status FROM pedidos e use um pedido que esteja Processando. Depois, teste um pedido inexistente e uma transição recusada. As chamadas inválidas devem mostrar erro e não devem executar o UPDATE.

3. Procedure avançada: registrar pedido (60 min)

Agora vamos construir sp_registrar_pedido, o exemplo do slide 11 da apresentação. Trabalhe em blocos. Compile e leia cada mensagem do MySQL antes de continuar.

Bloco A: contrato, variáveis e handler

  1. Receba cliente, produto e quantidade com parâmetros IN.
  2. Devolva o id do pedido e o frete com parâmetros OUT.
  3. Declare as variáveis locais antes de qualquer comando executável.
  4. Crie um EXIT HANDLER FOR SQLEXCEPTION que faça ROLLBACK e RESIGNAL.
  5. Inicie a transação.

Bloco B: validar os dados

  1. Se a quantidade for NULL ou menor que 1, devolva a mensagem Quantidade deve ser maior que zero.
  2. Busque o estado do cliente. Se não houver cliente, devolva Cliente não encontrado.
  3. Busque o preço e o estoque do produto com SELECT ... FOR UPDATE.
  4. Se o produto não existir, devolva Produto não encontrado.
  5. Se o estoque for menor que a quantidade, informe quantas unidades restam.

Bloco C: gravar e confirmar

  1. Insira em pedidos com cliente_id, data_pedido e status Processando. Use NOW() para a data.
  2. Guarde LAST_INSERT_ID() em p_pedido_id.
  3. Insira o item usando preco_unitario e o preço lido do produto.
  4. Diminua o estoque.
  5. Calcule o total com fn_total_pedido e o frete com fn_frete.
  6. Termine com COMMIT.

Chamada feliz

Rode uma vez no banco de laboratório:

CALL sp_registrar_pedido(1, 2, 2, @pedido, @frete);
SELECT @pedido AS pedido, @frete AS frete;
SELECT id, estoque FROM produtos WHERE id = 2;
SELECT * FROM itens_pedido WHERE pedido_id = @pedido;

Na carga inicial, o cliente 1 é de SP, o produto 2 custa R$ 80 e começa com 30 unidades. A chamada cria um pedido, devolve frete de R$ 15 e reduz o estoque em duas unidades. Ela altera a base de laboratório. Não a execute em uma base de produção nem repita sem restaurar os dados.

Chamadas que devem ser recusadas

Rode uma chamada por vez e anote a mensagem. Antes e depois dos testes, confira a quantidade de pedidos e o estoque dos produtos 2 e 10. Os valores devem permanecer iguais.

SELECT COUNT(*) AS total_pedidos FROM pedidos;
SELECT id, estoque FROM produtos WHERE id IN (2, 10);
SET @p = NULL; SET @f = NULL;
CALL sp_registrar_pedido(1, 2, 0, @p, @f);      -- quantidade inválida
SET @p = NULL; SET @f = NULL;
CALL sp_registrar_pedido(999, 2, 1, @p, @f);    -- cliente inexistente
SET @p = NULL; SET @f = NULL;
CALL sp_registrar_pedido(1, 999, 1, @p, @f);    -- produto inexistente
SET @p = NULL; SET @f = NULL;
CALL sp_registrar_pedido(1, 10, 99, @p, @f);    -- estoque insuficiente
SELECT COUNT(*) AS total_pedidos FROM pedidos;
SELECT id, estoque FROM produtos WHERE id IN (2, 10);
