Personalize os comandos

Preencha e os comandos e tabelas desta página passam a usar os seus dados. Fica salvo só neste navegador.

Ontem você subiu o seu nginx e viu na prática: o que fica dentro do contêiner morre com ele, o que fica no volume sobrevive.

Hoje você aplica isso ao que mais importa numa loja: o banco de dados. Primeiro, você coloca o MySQL da TechStore no ar, com os dados guardados num volume. Depois, você ensina o próprio banco a fazer contas da loja, criando as suas primeiras funções (UDF).

Para que serve esta aula: terminar o seu ambiente de homologação e começar a programar regras de negócio dentro do SGBD.

O que vamos observar:

  • se você sobe o MySQL com rede, porta, volume e limite de memória corretos e comprova que os dados sobrevivem ao contêiner;
  • se você escreve uma função que segue as regras pedidas pela loja e testa o resultado antes de dizer que está pronta.

3. Prática 2: seu servidor MySQL na rede da turma (30 min)

3.1 Bind mount × volume nomeado

Ontem você usou uma pasta sua (~/site) ligada ao contêiner. Isso se chama bind mount. Para o banco, vamos usar um volume nomeado: o próprio Docker cria e cuida da pasta.

Bind mount (ontem, nginx) Volume nomeado (hoje, MySQL)
Como se escreve -v ~/site:/usr/share/nginx/html -v dados-$USER:/var/lib/mysql
Onde fica Na pasta que você escolheu Numa área do Docker (/var/lib/docker/volumes/)
Quem cuida das permissões Você (lembra do chmod?) O Docker
Bom para Arquivos que você edita: site, configuração Dados de programas: banco de dados

3.2 Conhecer a rede

docker network ls
docker network inspect rede-turma

A rede-turma foi criada pelo professor. O phpMyAdmin da turma já está nela.

3.3 Definir a senha sem deixar no histórico

read -s -p "Senha do root do MySQL: " SENHA; echo

A variável SENHA só existe nesta sessão do terminal. Se você sair da VM e entrar de novo, rode esse comando outra vez.

3.4 Subir o MySQL

docker run -d --name mysql-$USER \
  --network rede-turma \
  -p 330NN:3306 \
  -v dados-$USER:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD="$SENHA" \
  --memory 512m \
  --restart unless-stopped \
  mysql:8.4
Parte O que faz
--network rede-turma Coloca o contêiner na rede da turma. O phpMyAdmin acha o banco pelo nome mysql-$USER.
-p 330NN:3306 Publica a porta do MySQL (3306 por dentro) na porta 330NN da VM.
-v dados-$USER:/var/lib/mysql Volume nomeado: os arquivos do banco ficam fora do contêiner.
-e MYSQL_ROOT_PASSWORD=... Define a senha do root só na primeira vez, quando o volume ainda está vazio.
--memory 512m Limite de memória. A VM é de toda a turma.
--restart unless-stopped Se a VM reiniciar, o contêiner volta sozinho.
mysql:8.4 Versão fixa. Em produção, não se usa latest.

Acompanhe a inicialização:

docker logs -f mysql-$USER

Quando aparecer ready for connections com port: 3306, aperte Ctrl + C (o contêiner continua rodando).

Veja o volume que o Docker criou:

docker volume ls --filter name=$USER
docker volume inspect dados-$USER

Repare no campo Mountpoint: é ali que os dados do seu banco moram.

5. Prática 4: carga da TechStore e prova de fogo (25 min)

5.1 Carregar a base

docker exec -i -e MYSQL_PWD="$SENHA" mysql-$USER \
  mysql -uroot --default-character-set=utf8mb4 < /srv/techstore/loja_teste_completo.sql

5.2 Conferir

docker exec -it -e MYSQL_PWD="$SENHA" mysql-$USER mysql -uroot loja_teste -e "
SELECT 'clientes' tabela, COUNT(*) total FROM clientes
UNION ALL SELECT 'produtos', COUNT(*) FROM produtos
UNION ALL SELECT 'pedidos', COUNT(*) FROM pedidos
UNION ALL SELECT 'itens_pedido', COUNT(*) FROM itens_pedido;"

Esperado: 25 clientes, 68 produtos, 27 pedidos, 35 itens. Confira também no phpMyAdmin.

5.3 Prova de fogo: apagar o servidor do banco

Agora o mesmo experimento de ontem, com o banco. Apague o contêiner:

docker rm -f mysql-$USER
docker ps -a --filter name=$USER      # o mysql sumiu
docker volume ls --filter name=$USER  # o volume continua

Suba de novo com exatamente o mesmo comando da seção 3.4 e espere o ready for connections. Depois, rode as contagens da 5.2 outra vez.

Os 25 clientes continuam lá. O contêiner é descartável. Os dados, não.

Repare: a senha continua a mesma de antes. Como o volume já tinha um banco, o MySQL ignorou o MYSQL_ROOT_PASSWORD.

  2. Print das contagens depois da prova de fogo (25, 68, 27, 35).

6. Variáveis e funções nativas (20 min)

O professor deixou o roteiro de hoje na VM. Copie para a sua pasta e abra o cliente do MySQL:

cp /srv/techstore/Aula02_funcoes_techstore.sql ~/
docker exec -it -e MYSQL_PWD="$SENHA" mysql-$USER \
  mysql -uroot --default-character-set=utf8mb4 loja_teste

O arquivo também está na pasta Data/ do repositório da UC. Você pode colar cada parte no terminal ou na aba SQL do phpMyAdmin.

Rode a Parte A do roteiro:

SET @desconto = 10;

SELECT nome, preco,
       ROUND(preco * (1 - @desconto / 100), 2) AS preco_promocional,
       IF(estoque < 10, 'Repor', 'OK')         AS situacao_estoque
FROM produtos
ORDER BY preco DESC
LIMIT 10;
Recurso O que faz
SET @desconto = 10 Cria uma variável de sessão. Ela vale até você sair do cliente.
ROUND(valor, 2) Arredonda para 2 casas.
IF(condição, sim, não) Escolhe um valor conforme a condição.
CONCAT, UPPER, DATEDIFF, CURDATE Juntar texto, maiúsculas, diferença entre datas, data de hoje.

Troque o valor de @desconto e rode de novo. O que muda?

7. Sua primeira função no servidor (UDF) (20 min)

Uma função definida pelo usuário (UDF) é uma regra que fica guardada dentro do banco. Qualquer sistema que use o banco (site, app, relatório) chama a mesma função e recebe o mesmo resultado.

CREATE FUNCTION fn_preco_com_desconto(p_preco DECIMAL(10,2), p_pct DECIMAL(5,2))
RETURNS DECIMAL(10,2)
DETERMINISTIC
RETURN ROUND(p_preco * (1 - p_pct / 100), 2);
Parte O que faz
fn_preco_com_desconto Nome da função. O prefixo fn_ ajuda a reconhecer.
(p_preco ..., p_pct ...) Parâmetros: o que a função recebe, cada um com o seu tipo.
RETURNS DECIMAL(10,2) Tipo do valor que ela devolve.
DETERMINISTIC Avisa que, para as mesmas entradas, o resultado é sempre o mesmo.
RETURN ... O cálculo devolvido.

Use como qualquer função nativa:

SELECT nome, preco, fn_preco_com_desconto(preco, 15) AS preco_black_friday
FROM produtos
WHERE categoria = 'Eletrônicos';

Função com mais de uma linha: DELIMITER

Quando a função tem um bloco BEGIN ... END, cada linha de dentro termina com ;. Para o cliente não achar que o comando acabou no primeiro ;, trocamos o delimitador por um tempo:

DELIMITER $$
CREATE FUNCTION ...
BEGIN
    ...;
    RETURN ...;
END $$
DELIMITER ;

No phpMyAdmin, a aba SQL tem o campo Delimitador. Coloque $$ ali e não escreva as linhas DELIMITER.

8. Desafio: a função de frete da TechStore (50 min, em duplas)

A equipe comercial mandou as regras de frete. Elas precisam valer igual no site, no app e nos relatórios. Por isso, a regra vai morar no banco.

Situação Frete
Pedido a partir de R$ 300,00 Grátis
SP R$ 15,00
RJ, MG, ES (Sudeste) R$ 25,00
PR, SC, RS (Sul) R$ 30,00
Demais estados R$ 45,00
  1. Abra a Parte C do roteiro (nano ~/Aula02_funcoes_techstore.sql) e complete o corpo da fn_frete. Use IF ... THEN ... ELSEIF ... ELSE ... END IF; ou CASE.
  2. Crie a função no seu banco.
  3. Rode os 5 testes do roteiro e compare com o esperado (15, 25, 30, 45 e 0).
  4. Combine com a sua dupla: um escreve, o outro confere os testes. Na próxima função, troquem.

Deu NULL nos testes? A variável v_frete não recebeu valor em nenhum caminho. Revise as condições.

Para quem terminar (Parte D): crie a fn_total_pedido(id), que soma quantidade * preco_unitario dos itens do pedido. Ela lê dados das tabelas, então use READS SQL DATA no lugar de DETERMINISTIC e SELECT ... INTO. Depois rode o relatório de pedidos com total e frete que está no roteiro.

9. Se algo der errado

Mensagem O que fazer
port is already allocated Confira o seu número na tabela e docker ps -a --filter name=$USER.
container name ... is already in use docker rm -f mysql-$USER e suba de novo (o volume continua).
Access denied for user 'root' A variável SENHA está vazia ou diferente. Rode o read -s de novo com a senha que você usou na primeira vez.
phpMyAdmin: getaddrinfo failed O MySQL não está na rede: docker network connect rede-turma mysql-$USER.
ERROR 1418 ... none of DETERMINISTIC, NO SQL, or READS SQL DATA Falta declarar o tipo da função. Acrescente DETERMINISTIC (só calcula) ou READS SQL DATA (lê tabelas).
ERROR 1304 ... FUNCTION ... already exists Rode DROP FUNCTION IF EXISTS nome_da_funcao; antes de criar de novo.
ERROR 1064 perto de END Faltou o DELIMITER $$ antes ou o $$ depois do END.

Regra de convivência: só mexa em contêineres e volumes com o seu nome.
