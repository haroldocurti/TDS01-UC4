A TechStore Brasil, a loja que você modelou na UC3, vai sair do laboratório e entrar em produção. Nesta UC, você faz parte da equipe de banco de dados que vai preparar esse servidor.

Hoje você vai montar o seu ambiente: um servidor web (nginx) e um servidor de banco (MySQL), acessíveis pela rede, com a base da TechStore carregada.

Para que serve esta aula: entender e configurar um ambiente de banco de dados em contêineres: imagens, portas, rede e armazenamento.

O que vamos observar: se você sobe e configura os serviços com os parâmetros certos, explica o que cada parte do comando faz e confere se tudo funciona.

3. Os conceitos de hoje

 Sua máquina / celular / colega
        │  http://IP-da-VM:80NN        http://IP-da-VM:8080
        ▼                               ▼
┌──────────────────────────── VM Ubuntu (Docker) ─────────────────────────────┐
│                                                                              │
│  porta 80NN ──► [ nginx-$USER ]:80                                           │
│                                                                              │
│  ┌──────────────── rede-turma (rede Docker) ────────────────┐               │
│  │                                                           │               │
│  │  porta 8080  ──► [ pma-turma ]:80  ──"mysql-$USER"──►  [ mysql-$USER ]:3306 ◄── porta 330NN
│  │                                                           │      │        │
│  └───────────────────────────────────────────────────────────┘      ▼        │
│                                                          volume dados-$USER  │
└──────────────────────────────────────────────────────────────────────────────┘
Conceito Em uma frase
Imagem O "molde" pronto, baixado do Docker Hub (ex.: nginx, mysql:8.4). Não muda.
Contêiner Uma cópia da imagem em execução. Você cria, para e apaga.
Porta O "número da porta de entrada". -p 8007:80 quer dizer: quem bater na porta 8007 da VM é levado para a porta 80 do contêiner.
Rede Docker Uma rede interna entre contêineres. Dentro dela, um contêiner acha o outro pelo nome (DNS), sem precisar de IP nem de porta publicada.
Volume Uma pasta guardada fora do contêiner. Se o contêiner for apagado, o volume continua. É ali que os dados do banco devem ficar.

4. Prática 1: seu servidor web (nginx)

4.1 Subir o contêiner

docker run -d --name nginx-$USER -p 80NN:80 nginx
Parte O que faz
docker run Cria e inicia um contêiner a partir de uma imagem.
-d Detached: roda em segundo plano e devolve o terminal.
--name nginx-$USER Dá um nome ao contêiner. Usar o seu usuário evita conflito com os colegas.
-p 80NN:80 Publica a porta: porta da VM : porta do contêiner. O nginx escuta na 80 por dentro.
nginx A imagem usada (sem versão = latest).

Confira:

docker ps --filter name=$USER      # só os seus contêineres
docker logs nginx-$USER            # o que o nginx escreveu ao iniciar

Abra no navegador: http://IP-da-VM:80NN. Você deve ver "Welcome to nginx!".

4.2 Entrar no contêiner e criar a sua página

docker exec -it nginx-$USER bash
Parte O que faz
docker exec Executa um comando dentro de um contêiner que já está rodando.
-it Modo interativo com terminal (para você digitar).
bash O comando executado: um shell.

Agora você está dentro do contêiner (o prompt muda). Crie a página:

echo "<h1>Servidor de $HOSTNAME</h1><p>Equipe de banco de dados da TechStore: SEU NOME</p>" > /usr/share/nginx/html/index.html
exit

Atualize o navegador. Depois abra a página de dois colegas, trocando só a porta.

4.3 Experimento: o que acontece se eu apagar o contêiner?

docker rm -f nginx-$USER                         # -f para e apaga de uma vez
docker run -d --name nginx-$USER -p 80NN:80 nginx

Abra a página. A sua página sumiu. Tudo o que é criado dentro do contêiner morre com ele.

Agora, com um volume (uma pasta da sua home ligada ao contêiner):

docker rm -f nginx-$USER
mkdir -p ~/site
echo "<h1>Página de SEU NOME que sobrevive</h1>" > ~/site/index.html
chmod o+x ~ && chmod -R o+r ~/site
docker run -d --name nginx-$USER -p 80NN:80 -v ~/site:/usr/share/nginx/html nginx
Parte O que faz
-v ~/site:/usr/share/nginx/html Liga a pasta ~/site da VM à pasta do site dentro do contêiner.
chmod ... Deixa o nginx ler a sua pasta. Sem isso, aparece 403 Forbidden.

Apague e suba de novo com o mesmo comando. A página continua. Guarde isso: com o banco de dados é igual.

5. Prática 2: seu servidor MySQL na rede da turma

5.1 Conhecer a rede

docker network ls
docker network inspect rede-turma

A rede-turma foi criada pelo professor. O phpMyAdmin da turma já está nela. O seu MySQL vai entrar nela também.

5.2 Definir a senha sem deixar no histórico

read -s -p "Senha do root do MySQL: " SENHA; echo

read -s lê a senha sem mostrar na tela e guarda na variável SENHA. Use uma senha só sua.

5.3 Subir o MySQL

docker run -d --name mysql-$USER \
  --network rede-turma \
  -p 330NN:3306 \
  -v dados-$USER:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD="$SENHA" \
  --memory 512m \
  --restart unless-stopped \
  mysql:8.4
Parte O que faz
--network rede-turma Coloca o contêiner na rede da turma. O phpMyAdmin passa a achar o banco pelo nome mysql-$USER.
-p 330NN:3306 Publica a porta do MySQL (3306 por dentro) na porta 330NN da VM, para acesso por programas de fora (ex.: Workbench, DBeaver).
-v dados-$USER:/var/lib/mysql Volume nomeado: os arquivos do banco ficam fora do contêiner.
-e MYSQL_ROOT_PASSWORD=... Variável de ambiente: define a senha do root na primeira inicialização.
--memory 512m Limite de memória. A VM é compartilhada por toda a turma.
--restart unless-stopped Se a VM reiniciar, o contêiner volta sozinho (menos downtime).
mysql:8.4 Imagem com versão fixa. Em produção, não se usa latest.

Espere o banco ficar pronto (leva cerca de 30 segundos na primeira vez):

docker logs -f mysql-$USER

Quando aparecer ready for connections com port: 3306, aperte Ctrl + C para sair do log (o contêiner continua rodando).

Confira em que rede e porta ele está:

docker ps --filter name=$USER
docker network inspect rede-turma --format '{{range .Containers}}{{.Name}} {{end}}'

6. Prática 3: phpMyAdmin da turma

  1. Abra http://IP-da-VM:8080.
  2. Servidor: mysql-SEU_USUARIO (o nome do seu contêiner).
  3. Usuário: root | Senha: a sua.

Por que funciona só com o nome? Porque o phpMyAdmin e o seu MySQL estão na mesma rede Docker, e o Docker resolve nomes de contêiner como se fossem endereços.

7. Prática 4: carga da base TechStore

O arquivo está na VM em /srv/techstore/loja_teste_completo.sql. Carregue pelo terminal:

docker exec -i -e MYSQL_PWD="$SENHA" mysql-$USER \
  mysql -uroot --default-character-set=utf8mb4 < /srv/techstore/loja_teste_completo.sql
Parte O que faz
docker exec -i Executa o cliente mysql dentro do contêiner, recebendo dados pela entrada padrão.
-e MYSQL_PWD=... Passa a senha ao cliente sem digitar no comando.
--default-character-set=utf8mb4 Garante os acentos corretos.
< arquivo.sql Envia o conteúdo do arquivo da VM para dentro do cliente.

Valide pelo terminal:

docker exec -it -e MYSQL_PWD="$SENHA" mysql-$USER mysql -uroot loja_teste -e "
SELECT 'clientes' tabela, COUNT(*) total FROM clientes
UNION ALL SELECT 'produtos', COUNT(*) FROM produtos
UNION ALL SELECT 'pedidos', COUNT(*) FROM pedidos
UNION ALL SELECT 'itens_pedido', COUNT(*) FROM itens_pedido;"

Resultado esperado: 25 clientes, 68 produtos, 27 pedidos, 35 itens.

Depois confira o mesmo banco no phpMyAdmin.

8. Se algo der errado

Mensagem O que fazer
port is already allocated A porta está em uso. Confira o seu número na tabela e docker ps -a --filter name=$USER.
container name ... is already in use docker rm -f NOME e suba de novo.
403 Forbidden no nginx Rode chmod o+x ~ && chmod -R o+r ~/site.
phpMyAdmin: Connection refused ou getaddrinfo failed O MySQL ainda está iniciando (veja o log) ou não está na rede: docker network connect rede-turma mysql-$USER.
Acentos estranhos Refaça a carga com --default-character-set=utf8mb4.

Regra de convivência: a VM é de todos. Só mexa em contêineres com o seu nome.
